# Presenter notes - Leader session a1: Why a number needs a tree

Audience: CxO, VPs, founders. 45 min, thinking-mode, no code. Room should leave able to
reframe "the number is down" into "which driver, and whose is it?"

## Run of show (45 min)
- 0-3 Welcome. One line: today is the mindset, not the maths. Ask for a recent bad number.
- 3-11 Part 1, live card "Why the number is down is useless". Anchor on the two-companies-down-8%
  story. Land: a top line is a lagging outcome, it says what not why.
- 11-15 Show the Part 1 SVG. Walk GMV -> Traffic x Conversion x AOV, and read the owner tags.
- 15-22 Part 2, live card. The blame-meeting-to-routed-question shift. Tell the DuPont story.
- 22-30 Part 2 self-study "exec who stared for a month" - tell it as a cautionary tale, ask the
  room who has lived it. This is the emotional peak; do not rush it.
- 30-42 Part 3, live card "three gifts, one trap". Show the ownership-map SVG. Emphasise the
  stopping rule - decompose only until the next level changes a decision.
- 42-45 Quiz live on projector (3 Qs), then Q&A.

## Likely exec questions + crisp answers
- "How deep should a tree go?" Until one more level would change who you call or what you do.
  Past that it is vanity depth.
- "We have forty KPIs already." That is a decomposition you have not done. Pick the one root,
  then build the tree beneath it.
- "Who owns a shared lever?" Nobody, in practice - which is the problem. One lever, one owner.
- "Isn't this just a KPI tree by another name?" Yes, done well. The discipline is ownership and
  a stopping rule, not the diagram.
- "What if we cannot agree on the root?" That disagreement is the real meeting. Lean Analytics:
  the root depends on model and stage - decide that first.
